# Pre-production QA audit — 2026-09-04

Scope: the whole app against the **live** Supabase project
(`ovscskaijvclaxelkdyf`), which is the backend every Lovable preview and the
published site share. The frontend under test was a production build of
`main` at `8e610e0` served locally, because no preview URL was available from
this environment and `hakiya.app` is blocked by its egress policy; nothing in
the findings depends on which host served the bundle.

Nothing has been fixed. Every item says which layer owns it: **frontend**,
**RLS**, **edge function**, **storage**, **migrations/deploy**, or **content**.

Companion artefacts, all reusable:

- `QA_MAP.md` — every route, its page, every table/RPC/function/bucket it
  reaches, the policy that gates each, and what the anon role really gets
  from production. Regenerate with `node qa/build-map.mjs`.
- `qa/` — the Playwright crawl, resilience and media specs, the report merger
  and the screenshot gallery (`qa/README.md` explains the switches).
- `qa/output/crawl-report.md` — the raw merged crawl output (per-route
  verdicts, every Supabase failure signature, no-op controls, paid controls).
- `qa/output/schema/` — the Phase-2 evidence files referenced below.
- `qa/output/gallery.html` — 161 screenshots, one per captured state (not
  committed; attached to the session).

## Blocking

### B1. The curriculum has no lessons in production
**Layer: content (not RLS).** `lessons` is empty. The SELECT policy is
`USING (true)` for anon and authenticated, the live probe returns
`content-range 0-0/0`, and `/curriculum` renders "No lessons yet for Gulf"
(the same for every dialect, since the filter is `dialect_module = <dialect>`
on an empty table). `curriculum_stages` has its six stages, so the page shows
six empty stages. `/learn/:lessonId` and `/quiz/:lessonId` are unreachable
except by URL, where they fall back to `topics` (three rows). Repro:
`GET /rest/v1/lessons?select=id&limit=1` with the publishable key → `[]`.
Either import the lesson spreadsheets (`/admin/lessons/import`) before launch
or hide the curriculum entry points until they exist.

### B2. Three paid edge functions are usable signed-out — by design, with a per-IP cap (corrected)
**Layer: edge function.** `practice-chunk-coach` (Munsit ASR + `askBrain`),
`score-set-phrase-voice` (Munsit ASR) and `scrape-x-post` (Jina) are
`verify_jwt = false` and answer callers with no `Authorization` header
(confirmed live: `POST {}` returns their validation error). The first draft of
this audit called them uncapped; that was wrong. Commit `d575aaf` ("Bound the
three endpoints that were unlimited paid calls for the anon key") gave them
`enforceAnonymousDailyCap` — 15, 60 and 20 calls per day per client IP, using
the proxy-appended last hop of `x-forwarded-for` — because the set-phrase
practice page and Learn-from-X are public. What remains is a judgement, not a
bug: a signed-out visitor can spend up to those per-IP ceilings per day. If
that is too generous, lower the limits or require sign-in (package 6 adds
the sign-in affordance those pages would need). Not a blocker. What *was*
wrong in this area, and is fixed in package 1: `check-subscription` returned
`500` for a caller the auth server rejects; it now returns `401`.

### B3. The migration replay is red on `main` — a duplicate policy migration
**Layer: migrations.** `20260903130627_1ec9b393-….sql` (Lovable-exported,
"Ledger updated, new migs added") re-creates the policies already created by
the hand-written `20260903100000_reviewer_content_writes.sql`. On a fresh
replay it fails at `CREATE POLICY "Content managers manage occasions"` and,
because the file is not transactional, the `set_phrases`, `dialect_rules` and
`dialect_rule_violations` policy changes after that line never apply. CI job
"Migration replay" has been red on `main` since `9bfc8f3` (runs 366 and 368).
This is the same failure class as B1 in the 2026-09-03 audit: a hand-written
migration gets re-exported by the dashboard under a UUID name. Production
state depends on which of the two files the ledger recorded; the anon probe
shows published `set_phrases` readable (2 rows), which is consistent with
either. Reduce the later file to `DROP POLICY IF EXISTS … ; CREATE POLICY`
(or delete it and reconcile `supabase_migrations.schema_migrations`).

## Major

### M1. Learners cannot get the hidden audio for TikTok videos, and every video page burns 6–12 failing storage calls
**Layer: storage policy + frontend.** `DiscoverVideo` resolves a video's
audio by asking the browser client for a **signed URL** in the private
`video-audio` bucket (`src/lib/videoAudioStaging.ts`), once per candidate
extension (`.wav .mp4 .m4a .webm .mp3 .opus`), then again keyed by the
YouTube id. The only SELECT policies on that bucket are
`can_review_transcripts()` and `is_admin()`, so a learner's request returns
`400 NoSuchKey` whether or not the object exists. Observed on every video
opened: 12 × `POST /storage/v1/object/sign/video-audio/… → 400` on the YouTube
sample, 12 on the TikTok sample (`qa/output/media/*.json`). For YouTube the
iframe carries its own sound so this is only noise; for the 18 published TikTok
videos the "hidden audio" path is the learner's only audio for slow-listen and
shadowing, and it can never succeed for a learner. Either grant
`authenticated` SELECT on published videos' audio, or mint the signed URL
server-side (an edge function under the service role) and stop probing six
extensions client-side.

### M2. `persist-video-thumbnail` is not deployed; TikTok thumbnails are expiring
**Layer: deploy.** The function added in PR #332 ("Keep our own copy of a
video still") answers `404 NOT_FOUND` on preflight while all 115 others answer
200 (`qa/output/schema/fn-preflight.txt`). The client calls it from
`useDiscoverVideos.ts:225` and `AdminVideoForm.tsx:630`. Meanwhile the
`thumbnail_url` of published TikTok videos still on `tiktokcdn.com` already
returns `403` (two samples checked), and one YouTube `maxresdefault.jpg`
returns `404`. Discover cards for those videos have no image until the
function is deployed and the backfill runs.

### M3. When Supabase is down, every page pretends it is empty
**Layer: frontend.** With every REST/functions/storage call answering 500, or
failing at the network layer, no route shows an error or a retry: `/` and
`/today` render the signed-out landing page, `/discover` says "No videos",
`/curriculum` "No lessons yet", `/leaderboard` "No rankings yet", `/stories`
"No stories yet", `/set-phrases` "No occasions yet", `/pricing` "Get started";
`/alphabet`, `/choose`, `/daily-challenge` look normal (static content). 22 of
22 outage runs were `silent-empty` or `looks-normal`; zero were `error-shown`
(`qa/output/crawl-report.md` → Resilience). The `ErrorBoundary` only catches
render throws; React Query errors are swallowed into empty arrays. A
back-end incident will look exactly like "the app has no content", to users
and to support. Add a shared query-error state (the `useQuery` `error`
branches) on the list pages at least, and surface `retry`.

### M4. Public pages call sign-in-only functions for anonymous visitors, and retry on 401
**Layer: frontend (call sites), one edge function.** On load, as a signed-out
visitor: `/set-phrases`, `/set-phrases/practice` and `/set-phrases/review`
post to `generate-set-phrase-quiz` **14 times** across the three pages
(`401 unauthenticated`) and then show "No phrases ready yet"; `/today` posts to
`phrase-of-the-day` 4 times (`401 auth_required`); `/discover/:id` (TikTok)
posts to `convert-to-fusha` (`401`); `/reading-library/:id` fired
`word-enrichment` 28 times during the click sweep; `/alphabet*` and `/learn`
fire `tts-speak`/`azure-tts` on tap and get `401` with no message shown. The
pages should gate these on a session (or show "sign in to…"), and React
Query's `retry: 1` should not retry a 401. Separately, `check-subscription`
returns **500** `"invalid claim: missing sub claim"` for a caller with only the
publishable key; it should be a 401 (the client does guard this call, but any
anonymous caller gets a 5xx that will show up as an error in logs).

### M5. Word-level timing exists for only a third of transcript lines
**Layer: pipeline/content.** Across the 49 published videos, 922/929 lines
carry `startMs/endMs`, but only 317 (34%) carry a `words[]` array with word
timings; the `tokens[]` on every line have no timing at all. Word highlighting
and tap-to-hear-the-word therefore fall back to line granularity on two thirds
of lines, including both media-spec samples (0/12 and 0/11 lines word-timed).
If word sync is a launch feature, `resync-transcript-timing` needs a backfill;
if not, the UI should not promise it. (Line timings are monotonic on every
video checked.)

### M6. Five production tables and one bucket exist outside the migrations
**Layer: migrations / disaster recovery.** `learning_paths`,
`processed_videos`, `review_streaks`, `user_difficulty`,
`weekly_recommendations` are in `types.ts` and answer on production, but no
migration creates them; `src/test/migrationReplay.test.ts` only knows about
two of the five. The `story-videos` bucket has a SELECT policy in a migration
and one object in production but no `INSERT INTO storage.buckets` anywhere.
55 tables also rely on Supabase's default privileges rather than explicit
`GRANT`s (the "Added missing GRANTs" commit on 2026-09-03 fixed some). A
rebuild from the repo would silently lose the leaderboard streak table and
the video-processing ledger.

## Minor

### m1. `/placement` "Go Back" leads to `about:blank`
**Frontend.** `PlacementQuiz.tsx:373` does `navigate(-1)`; when the quiz is
the first page in the tab (the landing page's "Try the placement quiz" opens
it directly for signed-out visitors) the crawl ended on `blank`. Use a real
destination when there is no history.

### m2. Controls that do nothing when clicked
**Frontend / content.** From the sweep (`crawl-report.md` → no-op section):
`/bridge` "I don't know MSA"; `/leaderboard` "This Week" (already the active
tab, so fine, but it should read as selected); `/learn` the speaker icon on
the mixed-mode card (every `vocabulary_words.audio_url` in the sample is
empty, so the button is live but silent); `/reading-library/:id` an unlabeled
icon button; `/login/id` "Sign in" with empty fields (native validation,
acceptable).

### m3. Controls Playwright could not click in 3s
**Frontend, verify by hand.** `/alphabet/:letterCode` "Gulf pronunciation",
"Fusha pronunciation", "Skip"; all eight "Practise X versus Y" cards on
`/alphabet/sounds`; the topic chips on `/conversation` and the word chips on
`/dialect-compare`; the two game cards on `/vocab-games`; "Show translation"
on `/stories/:storyId`; "Back to sign in" on `/reset-password`; 25 of 41
controls on the TikTok video page. A click timeout usually means an
overlapping element (a sticky footer, the assistant FAB, an iframe) or an
element inside a horizontally scrolling strip. Worth one manual pass on a
phone-sized viewport.

### m4. Listen episodes ship as uncompressed WAV with `no-cache`
**Storage / pipeline.** `listen-audio/episodes/<id>/full.wav` is 3.7 MB for one
episode and served with `cache-control: no-cache`, so every replay re-downloads
it. Encode to Opus/MP3 at generation time and let the public bucket cache.

### m5. Statement timeout on `caption_lines` with an exact count
**Database.** `select=*&limit=1` with `Prefer: count=exact` on `caption_lines`
returns `500 57014 canceling statement due to statement timeout`. No client
page counts that table today (the admin dashboard counts `vocabulary_words`
and `clip_candidates`), but any future "N captions" badge will hit it; add
an index or use `count=estimated`.

### m6. `tutor-audio-clips` is listable by anyone
**Storage.** The `lahja_public_read` policy makes learner-uploaded tutor
recordings publicly readable and the bucket listable with the publishable key
(folder names are user ids). Fine if the clips are meant to be shared;
otherwise scope reads to the owner like `learner-audio`.

### m7. `localhost:8080` is in the production `ALLOWED_ORIGINS`
**Edge function config.** Every function's preflight answers
`Access-Control-Allow-Origin: http://localhost:8080`. Harmless with the
publishable key, but it is a production allow-list entry nobody needs.

### m8. Landing page has two empty bands in a full-page capture
**Frontend, verify.** `qa/output/screens/root.anon.png` shows ~250px of
nothing under the hero CTA and ~300px under "Three dialects, three worlds"
where the dialect cards should be. Likely a scroll-triggered animation that
never fires in a headless full-page screenshot, but check that the cards
render without an intersection trigger (they are the primary navigation for
a new visitor).

### m9. Icon buttons without labels
**Frontend / a11y.** Several controls the sweep could only name by their icon
class (`lucide-volume2`, `lucide-heart`, "(unlabeled)"). Add `aria-label`s;
it also makes the crawl's paid-control filter reliable.

## Phase 2 detail — Supabase

### RLS
- Every table with RLS on has at least one policy; no table has RLS on with
  zero SELECT policies (`qa/output/schema/rls-policies.txt`, 329 policies).
- Content tables are public-read on `status = 'published'`/`published = true`
  and answer to anon in production: `discover_videos` 49, `vocabulary_words`
  82, `set_phrases` 2, `interactive_stories` 1, `authentic_stories` 1,
  `curriculum_stages` 6, `achievements` 10, `msa_transformation_rules` 44.
- Tables that answer **empty** to anon but whose policy would allow rows:
  `lessons` (B1), `daily_challenges`, `reading_passages`,
  `conversation_scenarios`, `grammar_exercises`, `listening_exercises`,
  `vocab_game_sets`, `meme_posts`, `published_clips`, `lesson_clips` — i.e.
  no published content yet. The routes that read them (`/daily-challenge`,
  `/reading`, `/conversation`, `/grammar`, `/listening`, `/vocab-games`,
  `/meme`, `/clips`) all fall back to on-the-fly generation or an empty state;
  none error.
- Authenticated-only reads (`listen_episodes`, `curriculum_concepts`,
  `dialect_rules`, `dialect_corpus_sentences`, `social_posts`,
  `trending_topics`) are only used on auth-gated or admin routes.
- Owner-read / service-role-write tables (`learner_errors`,
  `user_concept_mastery`, `learner_ai_memory`, `monologue_attempts`,
  `shadow_attempts`, `review_log`) have the owner SELECT policies the README
  describes.
- Client writes vs. write policies (`qa/output/schema/client-writes.txt`):
  39 tables are written from the browser; the three apparent gaps
  (`weekly_goals` INSERT/UPDATE, `anki_import_batches` UPDATE,
  `vocab_battles` DELETE) come from migrations that fail to replay
  (`20260529150401_…`), so they are unverified rather than known-broken —
  **needs the authenticated run** (Onboarding and Settings write
  `weekly_goals`).
- Anon is explicitly revoked on `dialect_corpus_sentences`, `social_posts`,
  `trending_topics` (`42501`), as intended.

### Edge functions
- 116 directories, 115 deployed; `persist-video-thumbnail` missing (M2).
- Guard classification: 112 resolve a user, enforce a cap, or check a role;
  `discover-feed` requires a JWT with a `sub` (401 otherwise, fine); three
  are unguarded (B2).
- 36 directories are absent from `config.toml` and inherit
  `verify_jwt = true`; the publishable key is a legacy JWT so they still
  answer anonymous callers — unchanged from the 2026-09-03 audit's note.
- **Logs not checked**: recent invocations and error rates need the
  dashboard (Edge Functions → Logs) or a management API token. `llm_usage_logs`
  and `client_errors` are admin-only under RLS, so they could not be read
  either.

## Phase 3 detail — crawl

- 126 page instances, 71 with a click sweep (the rest redirect to `/auth`
  or `/admin/login` as their gate says, or are the auth pages). No route
  404'd, went blank, or spun forever once the harness relayed Supabase
  traffic (an earlier pass without the relay produced false "infinite
  loader" results on every data page — that was the container, not the app).
- Unknown ids are handled: `/learn/<bad>` → "Topic not found / Go Home",
  `/discover/<bad>` → "This clip didn't load / Try again / Browse clips",
  `/stories/<bad>` and `/reading-library/<bad>` render their empty shells.
- Redirect routes (`/index`, `/skills`, `/learn-hub`, `/practice`,
  `/admin/transcribe`) all land where the manifest says.
- Full per-route table, failure signatures and control lists:
  `qa/output/crawl-report.md`.
